LifeBuddy：在手机本地运行的个人 Android AI 助手

最近一直在做自己的个人 Android AI 助手项目——LifeBuddy（小布），目前已经迭代到 0.2.0-alpha18，开源放在 GitHub 上，今天写一篇博客系统介绍一下它的设计思路、核心功能、实测效果和架构实现。

  • GitHub 仓库：https://github.com/RytterMohn/LifeBuddy
  • 测试版 APK 下载：Releases
  • 开源协议：MIT

一、为什么做 LifeBuddy？

现在桌面端的 Agent 工具已经非常多，但在手机端，大多数方案要么是纯聊天套壳，要么严重依赖云端中转后台，或者做成写死流程的“某某 App 专用脚本”。

我做 LifeBuddy 的初衷很直接：把 Agent 的执行循环、工具调用、记忆、技能和历史记录都留在 Android 本机运行，只把对话与单步规划交给用户自己配置的云端大模型。

给它一句自然语言目标，它会通过 Android 无障碍服务读取当前界面结构、选择合适的工具执行下一步，并在每一步之后重新观察和核对结果。默认无需在手机里下载体积庞大的本地大模型，开箱就能用。

二、核心能力

LifeBuddy 只保留了两个核心模式：聊天模式（问答、写作、读取技能资料）和操作模式（由模型根据目标自主选择应用和工具执行任务），不做僵化的“QQ 模式”或“外卖模式”。

能力模块 当前实现
多轮对话 流式回复（SSE）、Markdown 渲染、多轮上下文管理、内置计算器与时间工具
手机操作 打开应用、查找控件、点击、输入、搜索、滚动、返回，支持跨 App 协同任务
系统工具 闹钟、计时器、常见系统设置入口，以及页面支持的开关与滑块操作
历史与记忆 本机 SQLite 会话历史、检索与续聊；可编辑的长期记忆与习惯记录
从任务中学习 从有完成证据的成功流程中提取参数化试用技能，按需复用并管理失效版本
外部扩展 支持导入 SKILL.md / ZIP 技能包，支持连接 HTTPS MCP 工具服务
双语界面 支持跟随系统、中文、English，切换语言保留当前会话

三、实测演示：一句话自动发 QQ 消息

下面以一个真实任务为例，演示在 Operate（操作模式） 下输入一句自然语言指令：

“用 QQ 给 Rytter 发送一个 你好”

1. 主界面下达目标

在操作模式下直接输入目标，无需提前选择任何特定 App 模式，模型会自动决定需要打开的应用和工具：

2. 任务运行与悬浮控制条

开始执行后，顶部会出现悬浮状态条（LifeBuddy · Running），实时显示当前规划步骤，并且随时可以点击 Pause / Stop 接管或终止任务：

3. 完整执行轨迹与核对机制

整个任务共耗时 16 秒（4 次规划、0 次重规划、5 个步骤），每一步的工具调用、耗时和核对结果都会完整记录在历史中：

  • 第 1 步 phone_open_app：打开 QQ；
  • 第 2 步 phone_prepare_message：整理收件人与消息原文“你好”；

  • 第 3 步 phone_type：在已确认与 Rytter 的聊天输入框中填写正文并校验（Entered text verified）；
  • 第 4 步 phone_send_message：核对收件人与正文后点击发送；
  • 第 5 步 phone_verify_message：本机核对页面结果，且明确遵循“不盲目自动重发”的安全语义；

四、架构设计与关键机制

项目的架构参考了 Hermes、OpenCode、OpenClaw 等 Agent 在上下文、记忆和工具组织上的思路，并针对 Android 移动端场景做了完全重写。

1. 模块划分

其中 core/ 进一步拆分为 core/cloud（流式解析、工具配对、上下文预算与滚动摘要）、core/phone（页面协议、运行器、恢复预算与完成证据）、core/learning（参数化技能生成与失效管理）以及 core/extensions（技能导入、分页检索与 MCP 生命周期）。

2. 技能和 MCP 工具不全部塞进上下文

很多 Agent 一接多工具就会把上下文撑爆。LifeBuddy 采用的是按需检索加载：

  1. 先检索技能与工具摘要；
  2. 仅按需读取相关技能正文或某一个具体工具的参数定义；
  3. 最后再发起执行调用。

因此无论外部 MCP 服务暴露了多少个工具，模型侧始终只面对固定的搜索、读取和调用入口。仓库里也自带了 每日计划技能包 和 MCP JSON 模板 可以直接试用。

3. 单步规划与外部动作一致性

手机界面是动态变化的，一次性规划十步往往走到第二步页面就变了。LifeBuddy 在执行语义上做了几项约束：

  • 单步规划 + 页面变更校验：模型每次只规划下一步；如果在执行前页面已经发生变化，本机校验层会拒绝旧动作并进行有限重规划（单次任务上限 40 个步骤槽位、10 分钟）。
  • 执行意图先持久化：任何外部操作发出前先落盘记录执行意图；如果发出后遇到断线、取消或缺少足够证据，状态会保持待确认，网络层不会盲目自动重试 MCP tools/call，避免重复触发副作用。
  • 可随时接管：操作模式下随时可以暂停或停止，也能在设置中限定允许操作的应用白名单。

4. 长期记忆与技能自学习

  • 记忆：只保存用户明确表达的事实或偏好，不保存内部推理；习惯候选需要用户确认。
  • 自学习技能：基于带有完成证据的成功任务片段，将具体输入抽象为参数、剥离过期的界面节点和坐标，保留可复核的流程。当不同参数多次复用成功后会更新验证状态；一旦 App 改版导致连续失配，会自动暂停失效技能。

五、数据隐私与当前边界

数据放在哪里？

  • 会话历史、长期记忆、技能与执行记录全部保存在手机私有目录；
  • 模型 API Key 和 MCP 认证头通过 Android Keystore 加密存储；
  • LifeBuddy 不提供内置模型账号，也不经过任何自有中转服务器；
  • 不被动录制日常操作，不用你的手机数据训练模型。

当前版本边界（0.2.0-alpha18）

  • 手机控制依赖系统可访问的界面文字与控件树，纯自绘、无标签或纯视觉页面可能无法操作；
  • 暂不支持验证码处理、支付、外卖最终下单、持续后台无人值守以及桌面 stdio / npx 类 MCP 插件；
  • 本地 Gemma / llama.cpp 属于实验代码，默认 APK 不包含本地模型或原生推理库，目前手机操作仍使用云端规划。

六、快速上手与源码构建

直接体验

  1. 前往 Releases 下载最新测试版 APK 安装（要求 Android 8.0+）。
  2. 打开侧边栏 → 设置，填入支持 OpenAI Chat Completions / function tools 的 HTTPS API 地址、模型名和 API Key。
  3. 先在聊天模式确认模型连通，再在系统设置中开启 LifeBuddy 的无障碍服务。
  4. 切换到操作模式，可以先试一句简单指令，比如：

    “打开备忘录，新建一条写着 LifeBuddy 测试的笔记并保存。”

从源码构建

环境要求：JDK 17、Android SDK Platform 34、Build Tools 34.0.0（仓库自带 Gradle 8.9 Wrapper，普通构建不需要模型 Key 或 NDK）：

Windows 下将 ./gradlew 替换为 gradlew.bat 即可，构建产物位于 app/build/outputs/apk/debug/app-debug.apk。

七、写在最后

LifeBuddy 目前还在持续迭代中，很多真实 App 的页面适配和复杂跨应用流程也还在打磨。如果你对 Android Agent、无障碍自动化或者移动端 MCP 扩展感兴趣，欢迎去 GitHub 点个 Star，或者直接提 Issue / PR 一起交流！
